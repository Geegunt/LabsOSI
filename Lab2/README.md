# Лабораторная работа 2, вариант 4

Две программы на Си передают данные через неименованные каналы POSIX. Родитель принимает строки, ребёнок последовательно делит первое число типа `float` на остальные и записывает результаты в файл. Нулевой делитель проверяет ребёнок; после него оба процесса завершаются с кодом 2.

## Сборка и запуск

Нужны C-компилятор и Make. Запускать из папки проекта: родитель ищет дочернюю программу по пути `./child`.

```sh
make
./parent
```

Первой строкой ввести путь выходного файла, затем команды:

```text
results.txt
100 2 5
7.5 2.5
0 2
```

Закончить ввод: Ctrl+D в пустой строке терминала. В файле будут строки `10`, `3`, `0`. Существующий файл очищается при запуске. Пробелы в имени файла поддерживаются.

Проверка нуля:

```text
results.txt
20 2
10 0
```

В файле останется `10`. Оба процесса завершаются без дополнительного ввода.

## Соглашения

- Деление последовательное: `100 2 5` означает `(100 / 2) / 5`.
- Поддерживаются строки без фиксированного ограничения длины, в пределах доступной памяти. Одна команда — одна строка.
- Единственное число записывается как результат без деления.
- Десятичный разделитель — точка. Экспоненциальная запись поддерживается.
- Пустая команда, некорректное число, NUL внутри команды, `nan`, `inf`, выход преобразования за диапазон и неконечный результат приводят к ошибке и завершению обоих процессов. Ранее записанные результаты сохраняются.
- `0` в числителе допустим. `0` и `-0.0` в делителе завершают работу с кодом 2. Очень маленький ненулевой делитель не приравнивается к нулю; преобразования с `ERANGE` отклоняются.
- Результат вычисляется в `float` и выводится с `FLT_DECIMAL_DIG` значащими цифрами; на проверенной платформе это 9. Для некоторых десятичных дробей видна погрешность представления.
- Код завершения 0 — обычный конец ввода, 1 — ошибка, 2 — нулевой делитель.
- `pipe1` передаёт строки родителя в стандартный ввод ребёнка. `pipe2` передаёт статусы: `R` — готов, `K` — записано, `Z` — нулевой делитель, `E` — ошибка.
- Строки передаются по одной с ожиданием ответа. Числовые результаты записывает ребёнок непосредственно в файл. PID и диагностика идут в `stderr`.
- Если ребёнок извне уничтожен, пока родитель ждёт ответ, родитель обнаружит закрытие канала. Если родитель уже ждёт клавиатуру, ошибка обнаружится при следующем обмене. Для штатного завершения по нулю дополнительный ввод не нужен.

## Структура

- `parent.c` — каналы, запуск ребёнка, ввод, обмен и ожидание.
- `child.c` — чтение команд, деление, выходной файл.
- `ipc.c`, `ipc.h` — общие функции обмена и константы протокола.
- `tests/test_lab.py` — интеграционные проверки, требуется Python 3.
- `docs/lab2.tex` — исходник краткого отчёта.
- `docs/assets/` — реальные логи и результаты демонстрационных запусков.
- `output/pdf/lab2.pdf` — готовый PDF.

## Проверки

```sh
make test
```

В наборе 18 тестовых методов. В Debian 12 aarch64 с GCC 12.2 прошли все 18, включая `/dev/full`; лог сохранён в `docs/assets/linux/tests.log`. На macOS выполнены 17, проверка `/dev/full` пропущена, поскольку предназначена для Linux. Те же проверки прошли со сборкой AddressSanitizer и UndefinedBehaviorSanitizer. Статический анализ Clang не сообщил об ошибках. Искусственные отказы выделения памяти, `fork` и `pipe` не воспроизводились; обработка их ошибок есть в коде.

Дополнительная сборка с проверками памяти:

```sh
make clean
make CFLAGS='-std=c11 -Wall -Wextra -Wpedantic -Werror -g -O1 -fsanitize=address,undefined -fno-omit-frame-pointer'
make test
```

Для возврата к обычной сборке:

```sh
make clean
make
```

## Linux и защита

Проверено на macOS arm64 и в контейнере Debian 12 aarch64. 18 ноября 2026 года выполнены сборка GCC 12.2 с `-Werror`, все 18 тестов и два запуска под `strace`: обычное завершение и нулевой делитель. Реальные логи и трассировки находятся в `docs/assets/linux/`.

Повторная проверка через Docker Desktop:

```sh
sh tests/check_linux.sh
```

Для запуска непосредственно в Linux:

```sh
make clean
make
make test
strace -f -o trace.log ./parent
```

В трассировке видны создание каналов, создание процесса, перенаправление потоков, `execve`, запись результатов, закрытие дескрипторов и ожидание ребёнка. В проверенной Linux-среде `pipe`, `fork`, `dup2`, `waitpid` и `fopen` отображаются как `pipe2`, `clone`, `dup3`, `wait4` и `openat`.

## Пересборка PDF

Готовый PDF можно читать без установки LaTeX. Для пересборки нужен Tectonic и шрифты Times New Roman/Courier New с кириллицей:

```sh
make pdf
```

Если Tectonic расположен не в стандартном пути:

```sh
make pdf LATEX=/путь/к/tectonic
```

Краткий PDF занимает 4 страницы вместе с титульным листом. В нём указаны студент и группа, описаны реализация, ключевые фрагменты кода, реальные результаты проверки в Linux и выводы.
